# 论文与实验总流程

## 1. 研究问题

复杂运行状态会改变正常多变量响应。若模型只学习单一正常模式，罕见但正常的输入模式可能被误报；若又把可能异常的响应量直接当作状态，模型可能把异常吸收为“工况变化”。因此本项目先划分：

- **条件变量 (C)**：外部控制量或较慢状态，用来回答“系统在什么条件下运行”。
- **响应变量 (Y)**：研究目标及其电压、温度等结果量，用来预测、重构和形成报警。

状态编码器只读取 (C)，全局异常分数只聚合指定的 (Y)。这比笼统地“用原始数据感知工况”边界更清楚。

## 2. 两章递进

### 第三章：动态上下文条件化

MTAD-GAT 主干先获得局部、变量关系和时间关系表示：

```text
X -> Conv -> Feature GATv2 + Temporal GATv2 -> H_rel=[X,H_f,H_t]
C -> Temporal state encoder -> z
H'_rel = (1 + gamma(z)) ⊙ H_rel + beta(z)
H'_rel -> GRU + Transformer -> forecast/reconstruction -> response score
```

核心创新集中在两点：

1. 从条件通道学习窗口级连续上下文 (z)，不依赖离散工况标签。
2. 用 FiLM 在关系融合表示上条件化，使 GRU 和 Transformer 共同处理状态相关表示。

Transformer、双任务头和质量感知误差融合是框架组件，不单独宣称创新；RevIN 不进入正式模型。

### 第四章：电—热响应一致性

完整继承第三章，只增加：物理状态编码、响应一致性训练损失、测试期物理响应残差融合。使用“物理启发/响应一致性”，不称为完整 ECM，因为当前没有辨识 OCV、R0、RC 等参数。

## 3. 数据集职责与变量划分

| 数据集 | 条件变量 (C) | 报警响应 (Y) | 论文用途 |
| --- | --- | --- | --- |
| MSL | 通道 1–54 | 目标通道 0 | 通用上下文条件化；不解释为电池工况 |
| 清华 EV | 电流、SOC | 总电压、单体电压极值、温度极值 | 第三/四章电池主结果 |
| NASA Random Walk | 电流 | 电压、温度 | 冻结编码器后的电流方向表征探针，不做故障 F1 |
| 自有 BMS | 系统电流 `SYS_I`、簇 SOC | 簇电流 `BMSnI`、簇电压/温度及离散度 | 调频案例与误报警分析，无监督指标 |

MSL 没有物理语义，(z) 只能称为“潜在运行上下文”，并关闭电流/SOC描述辅助任务。BMS 不用簇电流作为条件，是为了保留簇级异常电流的可检性。

若 BMS 的“单个电池”指某个并联簇，可检测其电流相对系统电流的异常关系；若指串联电芯，数据没有单体电流，只能从单体电压/温度离散间接发现不一致，不能声称直接检测单体过流。

## 4. 训练与评分流程

1. 按航天器实体、充电片段、电池或 BMS 簇划分，禁止跨边界取窗。
2. 缩放器只拟合正常训练数据；所有电池数据的电流均保持零点和符号。
3. 训练预测与重构双任务；有明确电流/SOC语义时增加动态描述辅助损失。
4. 正常验证集确定预测/重构融合权重和阈值，测试标签不参与调参。
5. 先得到各输出通道误差，再只聚合响应维度形成全局分数。
6. 清华窗口分数取 top-5% 均值形成片段分数；MSL 保留时间点分数；BMS 报告分布和案例。

## 5. 实验矩阵与指标

### 第三章

- 主对比：MTAD-GAT、完整 C3、TranAD、GDN、Anomaly Transformer、DCdetector（以实际成功复现为准）。
- 消融：无条件化、统计量编码器、无辅助任务、旧 Transformer 残差门控、固定预测/重构融合。
- MSL：raw AUPRC 为主，point-F1、precision、recall、AUROC 和 event 指标为辅；point-adjusted 仅附录。
- 清华：片段级 AUROC、AUPRC；正常校准集阈值下的 F1、Recall、FPR。

### 第四章

- 加法递进：`C3 -> + physical state -> + response loss -> + response score`。
- 留一消融：电压响应、温度响应、电荷流、SOC—电流耦合。
- 同时报告响应 MAE、三种子均值/标准差、参数量、延迟、吞吐和显存。

NASA 只报告工步线性探针 macro-F1/accuracy；BMS 无可靠异常标签，只报告告警率、静置/调频分数、切换邻域告警率和典型案例，不报告监督 F1/AUROC。

## 6. 执行顺序

1. `00_kaggle_smoke.json`：环境和完整链路。
2. `01_ch3_main.json`：MSL、清华主结果。
3. `02_ch3_regime_ablation.json`：确认状态编码与 FiLM 条件化贡献。
4. `03_ch4_tsinghua_main.json`、`04_ch4_physics_ablation.json`：第四章递进与消融。
5. `05_condition_validation.json`：NASA 表征探针和 BMS 案例。

主结果使用 3 个随机种子；诊断性消融可先用 seed 3407。公开清华包没有车辆 ID，因此只报告充电片段级效果，不宣称车辆独立泛化。

## 7. 写作边界

- 不把变量/时间全连接注意力图写成电池拓扑图。
- 不把连续上下文向量写成已识别的离散工况，除非探针实验支持。
- 不把 BMS 无标签案例写成已验证故障检测性能。
- 不把响应一致性写成严格物理定律或等效电路模型。
- 在消融和三种子结果完成前，只写“提出/设计”，不写“显著提升”。
