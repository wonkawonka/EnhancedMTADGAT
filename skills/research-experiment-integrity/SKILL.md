# 科研对比实验完整性

目标是让用户知道实际比较了什么，并让结论有可追溯证据。脚本通过、引用论文、使用同名类都不能证明忠实复现。遵守用户已确认的范围、预算和协议；不替用户扩大实验矩阵。

## 先明确比较对象

- 区分原论文复现、外部模型在电池数据上的适配、项目结构消融、预算受限筛选。不同问题不能混用一个结论。
- 外部主对比优先用原论文及作者实现可核验的推荐参数。共同数据和评价规则不意味着所有模型共用窗口、优化器、学习率、损失或训练器。
- 逐模型记录论文、仓库来源、代码版本以及实际调用路径。明确是作者实现、第三方复现还是项目改写；第三方仓库不能因流行或名称一致而标为官方。
- 有多个数据集配置时，不凭测试结果挑一个，也不把某原数据集最优值称为电池数据推荐值。记录采用的默认值、适用范围和理由。论文与代码冲突、版本不明或实现缺项时，保留未解决项。
- 禁止把简化 GRU-VAE、替代注意力或删减模块以原模型名混入正式主表。合法变体须另命名、披露差异，经用户确认才运行；不能用措辞替代修复。

## 形成可核验协议

在 `configs/` 的实验 plan 中记录实际配置；用户审阅前标为草案，未解决的值不得用猜测补齐。向用户展示“取值、原因、出处、与旧实验差异”的简表。

| 类别 | 必须明确的内容 |
| --- | --- |
| 数据任务 | 数据版本、变量及顺序、单位、标签粒度、正常定义、实体/片段/时间划分、重叠与去重、缺失值和异常值处理、采样频率、允许使用的信息 |
| 数据使用 | 训练/验证/测试样本 ID 与计数、是否全量、任何上限及单位、抽样算法、归一化拟合范围、泄漏检查 |
| 时序输入输出 | 窗口、步长、目标偏移、因果性、片段边界、短片段/尾部/补齐规则、输入覆盖与实际产生分数的覆盖、重叠窗口回填 |
| 方法本体 | 编码/解码、注意力与位置编码、掩码、预测或重构目标、损失公式/权重/调度、梯度流、异常分数公式/温度/方向/降维 |
| 训练选择 | 每模型优化器、学习率与调度、权重衰减、有效 batch、精度、梯度累积/裁剪、种子、预训练/训练阶段、epoch/step 定义、验证目标、早停与 checkpoint 选择 |
| 评价 | 相同测试对象、评分粒度、跨时间/变量/实体聚合、校准拟合范围、阈值来源、是否 point adjustment、AP 与 PR-AUC 的实现区别、折/种子汇总方式 |
| 预算来源 | 官方设置、用户指定、项目约定、工程限制分别标注；调参搜索空间/次数/选择规则；预计时空开销及估计依据 |

具体数值必须有出处或明确标为项目选择。不得说“30 轮 / patience=8 / 10 万窗口是通行标准”。相同 epoch 不等于相同更新次数、计算量或收敛程度。参数调优依据独立验证信息并预先限定预算；不得用测试 AP/F1 选窗口、模型、权重、阈值或停止时机。正常验证重构损失是代理目标，不等于异常检测性能。

复用原生评分，统一预先声明的外部评价规则。不能为方便而把所有模型改为 MSE 异常评分，也不能把 RCR 校准偷偷加给外部模型。原仓库若以测试标签选阈值/权重，不盲目照搬；披露并提出独立验证替代规则，或将测试最优阈值结果明确单列为 oracle 分析。

## 三类证据各负其责

1. **源码人工核对**：对照论文/参考实现和实际 runner，检查本轮涉及的结构、前向目标、训练梯度、验证和评分路径；记录文件/函数及差异。不能只看命令行参数或类名。
2. **针对性数值检查**：对改动的数据适配/模型包装，用小型固定输入验证时刻对齐、掩码泄漏、损失及必要梯度、评分与参考实现一致性。只测真实风险；无基准或未核对的部分写清楚，不能宣称全模型等价。
3. **机械检查**：核验实际解析参数、样本集合、片段边界、有效时间覆盖、归一化拟合来源、版本/文件哈希和产物映射。读取必要元数据，避免遍历全部权重和日志。字段一致不证明字段内容正确。

首次适配、改动窗口/评分或审计旧实现时，读取 [参考依据与失败案例](references/evidence-and-cases.md)。检查结果区分已验证、未验证、不适用；不得自动把未验证算通过。

## 审阅、执行与变更

- 源码阅读、差异整理、草案和轻量 CPU 检查可以先做。实际协议、可选方案及影响应具体到可审阅，再提出必须的确认。
- 用户已确认的原样协议不重复请示。首次协议或实质改动必须在昂贵运行前取得用户确认，这是本项目用户明确要求；“继续 / 公平对比 / 与 RCR 统一”不授权未披露的改法。
- 更改模型来源/结构/目标/损失/评分、有效窗口/覆盖、训练数据/预算、选权重/阈值规则属于实质改动。batch、AMP、编译、缓存、并行等优化也要核对是否改变数值或数据顺序；不能一律称为纯加速。
- 按 AGENTS.md 确认命令、设备、显存、输出；CUDA 检查在沙箱外。先完成已授权的最小运行核验，再启动整批长任务。遇到 OOM、依赖失败、NaN 或无效验证量，停止受影响单元并报告，禁止静默降模型、减数据、换损失或重复消耗预算。
- 保存 plan、有效参数、代码/环境版本（含未提交改动）、split/样本映射、必要覆盖统计、曲线、checkpoint 选择依据、分数和指标。实质变更新建任务/输出目录，不覆盖旧产物或改旧 manifest 来宣称旧结果符合新协议。
- 本地与 Kaggle 共用同一冻结协议；Kaggle 账号、版本与 Output 核验遵循 AGENTS.md。只上传/提交已授权内容。

## 结论边界

同一主表需有可比的样本、标签粒度和评价；缺失、失败、预算限制与旧协议结果显式标记，不挑折、不以最好种子冒充平均值。seed 波动和数据折波动分别计算。改变多个因素不能单独归因于其中一个。

既有测试集已反复查看时，不声称新计划是从未接触测试的确认性实验。需要新的确认性证据时另提独立保留集方案，不能擅自重划已有数据。外部基线不忠实不自动否定内部消融，也不支持 RCR 已经优于原论文模型。

只在用户要求或整合结果时写结果报告，遵守既有四表版式。协议留在 config，核对证据随任务归档，不新增重复叙述报告。
